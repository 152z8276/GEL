## 2. Unity 引擎知识（按项目映射）

### 2.1 MonoBehaviour 生命周期

| 回调 | 执行时机 | 项目里怎么用 |
|---|---|---|
| `Awake` | 对象加载时，早于 Start | 缓存组件、初始化参数 |
| `OnEnable` | 每次启用 | 订阅事件/重置状态 |
| `Start` | 第一帧前 | 依赖其他对象的初始化 |
| `FixedUpdate` | 固定时间步，物理帧 | Rigidbody、球物理、爆发计时 |
| `Update` | 每帧 | 输入、手势采样、普通计时 |
| `LateUpdate` | 所有 Update 后 | 相机跟随、程序化骨骼覆盖 |
| `OnDisable` / `OnDestroy` | 禁用/销毁 | 取消订阅、停止协程 |

**追问点：为什么程序化腿在 `LateUpdate`？**

因为 Animator 在 Update 阶段写入骨骼；如果在 Update 改骨骼，会被 Animator 覆盖。放到 LateUpdate 可以在动画采样之后覆盖腿部姿态，动作结束再恢复基础姿态。

**追问点：为什么球物理在 FixedUpdate？**

Rigidbody 和碰撞在物理步中更新；用 `FixedUpdate` 才能与物理时间一致。普通视觉跟随可以放在 Update/LateUpdate。

### 2.2 Transform、旋转与坐标

- `Transform.position` 世界坐标，`localPosition` 相对父节点。
- `Transform.forward/right/up` 是本地轴在世界空间的方向。
- 旋转优先用 `Quaternion`；欧拉角只适合编辑器和简单展示，连续旋转容易万向锁。
- `Quaternion.LookRotation` / `Quaternion.Slerp` 用于朝向和阻尼。
- `Vector3.ProjectOnPlane(v, Vector3.up)` 取水平分量，是越肩移动/手势方向映射的关键。

**项目应用：**

- 手势方向：`forward * tangent.y + right * tangent.x`，再 `y=0`。
- 相机 yaw 始终跟玩家身体朝向，A/D 转身时镜头同步，但 S 后撤时镜头不猛转。
- 花式骨骼只旋转可视层，不旋转 root 和相机，避免镜头被动作带偏。

### 2.3 物理与碰撞

| 概念 | 要点 | 项目应用 |
|---|---|---|
| Rigidbody | 物理驱动 | 球、球员 |
| Collider | 碰撞形状 | 胶囊、球、边界 |
| Trigger | 不产生物理分离 | 进球检测 |
| `MovePosition` | 物理帧移动 Rigidbody | 球员移动 |
| `AddForce` / `velocity` | 力/速度 | 射门、爆发 |
| 碰撞矩阵 | 分层过滤 | 球、球员、边界、球门 |
| `Physics.SyncTransforms` | 手动同步 Transform | 程序化场景后立即查询 |

**项目应用：**

- 球是自定义物理，不是纯 Transform 动画；曲线射门用二次贝塞尔目标点 + 物理速度。
- 球权是逻辑层，碰撞是物理层；持球时球跟随，但爆发期间球权硬锁，避免“刚做完动作球被吸走”。
- 边界、门线、顶棚都是碰撞体；球场是封闭体，暂时没有出界规则。

### 2.4 Input System（旧 Input Manager）

- `Input.GetMouseButton(0)`、`Input.mousePosition`。
- `Input.touchCount` / `Input.GetTouch(i)`：`Began`、`Moved`、`Stationary`、`Ended`、`Canceled`。
- 屏幕坐标原点在左下，UI 坐标原点通常左上；两套坐标不要混。
- `Screen.height` 缩放命中圈，避免只适配 1440p。
- `MobileControls.IsTouchOnUi` 防止摇杆/按钮区域误触手势。

**项目输入规则：**

```text
PointerDown
  ├─ 在球命中圈内 → Shot（后续不再改判）
  └─ 在球命中圈外 → Dribble
Release
  ├─ Shot：拟合弹道
  └─ Dribble：
       ├─ 路径近似直线 → Simple Burst
       └─ 路径明显弯折 → Elastico
```

**项目应用：**

- 摇杆和手势可同时存在，用 `fingerId` 追踪手势手指。
- 触摸采样不足时，快速手势可能只有 2–3 个点；识别器至少需要 3 个点。
- 球上严格射门是产品规则，不是识别结果。

### 2.5 Animator 与 Humanoid

| 概念 | 要点 |
|---|---|
| Animator Controller | 状态机、参数、过渡 |
| Trigger | 一次性动作触发 |
| Root Motion | 动画驱动位移；本项目关闭，位移由代码控制 |
| Humanoid | 统一人形骨骼，可复用 Mixamo 动作 |
| Avatar | 骨骼映射 |
| Layer / Mask | 上下半身分层 |
| `Animator.Update(0)` | 立即采样一帧，常用于程序化覆盖前 |

**项目应用：**

- 玩家 ybot、AI xbot，使用 Humanoid。
- `PlayerAnimationDriver` 读取 `Motor.ConsumeDribbleAnimationTrigger()`，设置 Animator Trigger。
- `PlayerVisual` 缓存左右大腿、小腿、脚骨；Elastico 时在 LateUpdate 覆盖腿部姿态。
- 严格说这是**程序化占位动作**，不是正式动捕。

### 2.6 相机

- 相机跟随用 `LateUpdate`，避免看到上一帧位置。
- `Vector3.SmoothDamp` 做位置阻尼，`Quaternion.Slerp` 做旋转阻尼。
- FOV 从 58° 拉到 42° 形成“拉近”感；同时降低相机高度、抬高视线。
- 镜头要保证球、球门、AI、玩家脚在画面内；不能只看球。
- 移动端要提供“减少镜头拉近/动态 FOV”选项，降低晕动。

### 2.7 渲染与材质

- Built-in Render Pipeline；透明材质、半透明穹顶会增加 overdraw。
- 半透明物体要控制层数；不要多层大面积透明叠加。
- 程序化材质使用 `Material` / `Shader` 属性；颜色和发光参数可运行时改。
- 目前只做了穹顶呼吸、电路纹理、能量核心；没有后处理、粒子、镜头震动。

**移动端性能追问：**

- 透明穹顶是 overdraw 大户；低画质可以关闭电路动画、减少透明层。
- 减少 `FindObjectOfType`、每帧字符串拼接、临时 List 分配。
- UI 从 OnGUI 迁到 UGUI，减少每帧 IMGUI 布局。
- 用 Profiler 看 CPU Main Thread、GC Alloc、Batches、Tris。

### 2.8 UI

| 方案 | 特点 | 项目状态 |
|---|---|---|
| OnGUI / IMGUI | 快速原型，每帧重建，不适合正式 UI | 当前临时 HUD |
| UGUI Canvas | 正式项目常用，支持锚点、安全区、动画 | 计划 |
| UI Toolkit | 编辑器/运行时新方案 | 未使用 |

正式版要处理：刘海安全区、横屏、不同分辨率、触控按钮最小尺寸、HUD 与手势区域互斥。

### 2.9 构建与 Android

- Player Settings：横屏、包名、API Level、ARM64、IL2CPP。
- Android SDK/NDK、JDK、Gradle 版本要匹配。
- 构建失败先看 Editor.log / Gradle 日志，不要只看 Unity 弹窗。
- 当前项目有构建脚本，但未产出 APK；面试时如实说“代码与构建配置已准备，真机链路未完成”。

### 2.10 Editor 脚本与程序化场景

- `[MenuItem]` 自定义菜单。
- `AssetDatabase.Refresh` / `CreateAsset` / `SaveAssets`。
- 程序化 Mesh、材质、Prefab，适合快速搭灰盒。
- 一键场景构建器的价值：可重复、可回滚、少手工引用丢失。
- 风险：生成物和场景文件容易产生大量 Git 脏状态，需要明确“源文件 vs 生成物”。

## 3. C# 与代码知识

### 3.1 语言基础

- `class` 引用类型，`struct` 值类型；Vector3 是 struct，赋值时复制。
- `List<T>` 动态数组；避免每帧 `new List`，可复用。
- `out` 参数用于返回多个结果（识别器的 confidence / angle）。
- `event` / `Action` 做解耦；本项目以直接引用为主，正式版可改事件。
- 协程适合“按时间分步”，但受 `Time.timeScale` 影响；需要真实时间用 `WaitForSecondsRealtime`。
- `ScriptableObject` 适合配置数值和识别阈值，避免硬编码。

### 3.2 向量数学

| 公式 | 用途 |
|---|---|
| `Vector2.Distance` | 采样路径长度 |
| `Vector2.Angle(a,b)` | 两方向夹角 |
| `Vector2.Dot` | 投影、前后判断 |
| `Vector3.Cross` | 左右/法线 |
| `Vector3.ProjectOnPlane` | 水平移动方向 |
| 点到直线距离 | 判断路径是否近似直线 |
| 二次贝塞尔 | 射门弧线 |
| 切向量 | 手势最后一段方向 |

**关键代码逻辑：**

```csharp
// 直线/非直线二元判定
float deviationRatio = maxDeviation / pathLength;
float pathRatio = pathLength / chordLength;
bool straight = deviationRatio <= 0.05f && pathRatio <= 1.10f;
return straight ? DribbleStyle.Simple : DribbleStyle.Elastico;
```

```csharp
// 末段切线，而不是起点到终点的净位移
int startIndex = Mathf.Max(0, points.Count - sampleCount);
Vector2 tangent = (last - points[startIndex]).normalized;
Vector3 dir = forward * tangent.y + right * tangent.x;
```

### 3.3 架构与状态

- 输入状态机：`None / Shot / Dribble`，用 `_mode` 显式管理。
- 动作锁：`_dribbleInputLockTimer`、`_dribbleCooldownTimer` 防止连点。
- 球权硬锁：动作期间禁止抢断/吸附，避免逻辑竞争。
- 慢动作：`Time.timeScale` 是全局的，必须让 UI/输入/计时知道当前状态。
- 配置外置：P1 把阈值从代码常量搬到 ScriptableObject。

### 3.4 性能与调试

- `FindObjectOfType` 只在初始化用，不每帧调用。
- 缓存 `Animator`、`Rigidbody`、`Camera`、骨骼 Transform。
- 避免每帧 `string` 拼接；HUD 只在变化时更新。
- 用 `Debug.Log` + 时间戳/点数量定位识别问题；正式版可做可视化轨迹。
- Git 小步提交 + 阶段标签，手感项目尤其需要可回退。

## 4. 项目关键实现（5 分钟讲法）

### 4.1 射门

1. 手指按在球命中圈内，`GestureInput` 锁定 `Shot`。
2. 拖动采样屏幕点，松手后按屏幕曲线拟合射门弧线。
3. `PlayerMotor` 进入 0.35s 前摇，球缓慢前移；松手后退出子弹时间，球以二次贝塞尔轨迹飞出。
4. 弧线有曲率/横向偏移上限，避免一脚从边线绕回球门。

### 4.2 射门/花式争抢的解决

- 球上永远射门；球外才进入 Dribble。
- 球外不再做五种手势分类，只做直线/非直线二元分类。
- 好处：输入规则可解释、可测试；不会因为“像牛尾巴”而抢走射门。
- 代价：目前只有一种花式，表现层不够丰富。

### 4.3 牛尾巴

- 识别：路径和起终点弦的最大偏离 ≤ 5% 且路径/弦 ≤ 1.10 → 直线；否则花式。
- 方向：最后一段切线，映射到相机水平轴。
- 动作：`PlayerVisual` 在 LateUpdate 对大腿/小腿/脚做旋转，0.34s。
- 位移：`PlayerMotor` 在 commit 时给 0.5m 即时位移 + 0.12s 峰值速度 16m/s 的爆发。
- 演出：`SlowMotionController.ForceEnter(0.60f)` + 相机拉近。

### 4.4 子弹时间

- 射门/花式/近身自动触发；手动 Space 也可。
- `Time.timeScale` 降低到 0.25 左右；相机按 `Time.timeScale < SlowThreshold` 进入 zoom。
- 风险：动作计时也变慢，所以爆发要强制实时或退出慢动作；否则看起来“慢动作里慢走”。

### 4.5 AI 与抢断

- AI 有 0.18s 反应延迟，读取玩家重心并偏移。
- 抢断按最近脚到球的距离、能力、随机扰动计算成功率，限制 5%–90%。
- 成功/失败都有僵直和冷却，避免无限连抢。

### 4.6 球场

- 42×26m，球门线 x=±18，边线 z=±12。
- 半胶囊穹顶 + 电路纹理 + 四角三段式科技柱。
- 草坪程序纹理、割草条纹、禁区/中圈/角球弧。
- 封闭边界，没有出界规则。

## 5. 面试问题库

> 先给“答题骨架”，不要背长篇。面试时用项目里的具体文件/数字支撑。

### 5.1 项目类

**Q1. 用 1 分钟介绍这个项目。**

A：项目目标是验证“手势射门 + 子弹时间”在手机 1v1 足球里是否有身体感。我独立完成 Unity 原型，包含越肩移动、球上起手射门、球外直线爆发/弯折牛尾巴、抢断与 AI、程序化科技球场。当前是 P0，可玩闭环完成；正式动作、音效、UGUI 和 Android 真机包是下一步。

**Q2. 为什么做 1v1，不做 11v11？**

A：验证核心手感不需要 22 个球员。1v1 能把输入、球权、抢断、镜头和慢动作的因果关系压缩到一局 2 分钟里，迭代成本低。

**Q3. 你做的最关键设计决策是什么？**

A：把输入拆成“起点区域 + 路径形状”两层。起点决定射门还是动作，路径只决定直线还是弯折。这样射门/花式不会互相抢判，规则也能被玩家一眼理解。

**Q4. 为什么球上起手必须射门？**

A：球是射门的语义中心。如果球上也能触发花式，玩家无法预测松手会发生什么。把球上锁死为 Shot 是用“可预测性”换“动作丰富度”。

**Q5. 为什么直线/弯折用 5% 和 1.10？**

A：这是手感阈值，不是物理常量。5% 能容忍手指抖动，1.10 能区分“直线滑”与“明显折返”；阈值需要真机采样后调，当前只是可运行值。

**Q6. 为什么突进方向取末段切线，而不是起点到终点的方向？**

A：玩家画 `>` 时，起点和终点可能在同一侧，净位移方向会指向“上方”，但手指最后一段其实在往左上/右上。末段切线更接近玩家松手瞬间的意图。

**Q7. 子弹时间不会影响操作吗？**

A：会影响所有基于 `Time.timeScale` 的计时。所以我把 UI 和输入用 unscaled 时间，爆发位移用实时/强制退出处理，避免慢动作里动作也变慢。

**Q8. 这个项目最难的部分？**

A：不是写某个功能，而是让输入、球权、动作锁、镜头和慢动作不互相打架。比如爆发期间必须锁球权，否则刚拨出去的球会被吸附；花式不能转 root，否则镜头会突然甩。

**Q9. 你做过但效果不好的方案？**

A：一开始用五种手势分类（Feint/Roulette/DoubleTouch/StepOver/Elastico），结果直线爆发和花式互相误判，HUD 经常显示 Dribble 或 Beat。后来砍成二元分类，并显式显示识别风格，问题才可诊断。

**Q10. 如果给你两周，你优先做什么？**

A：第一周做 Android 真机 + 触摸采样 + 动作/音效反馈；第二周做 UGUI 教学/结算和一次 10 人可玩性测试。不会先加第二套花式。

**Q11. 这个项目有什么没做？**

A：Android APK、正式 UI、音频、VFX、正式动作资产、门将、联网、性能数据。当前只有 P0 闭环和程序化占位。

**Q12. 你怎么验证“好玩”？**

A：先定义可观察指标：第一次射门时间、花式识别成功率、射门/花式使用比、单局进球数、重开率；再做 5–10 人定性测试，问“你刚才想做什么，游戏做了什么”。

### 5.2 Unity 类

**Q13. Awake 和 Start 的区别？**

A：Awake 在对象加载时调用，适合缓存自身组件；Start 在第一帧前、所有 Awake 后调用，适合依赖其他对象。OnEnable 每次启用都调用。

**Q14. Update 和 FixedUpdate 的区别？**

A：Update 每帧，受帧率影响；FixedUpdate 固定时间步，物理相关。Rigidbody 用 FixedUpdate，输入采样和视觉用 Update。

**Q15. 为什么用 LateUpdate 做相机/骨骼？**

A：相机要在角色移动后跟随；骨骼要在 Animator 写入后覆盖。LateUpdate 在 Update 之后，适合这两类“最终修正”。

**Q16. Rigidbody 移动和 Transform 移动的区别？**

A：Transform 直接改位置会绕过物理插值/碰撞求解，容易穿模；Rigidbody.MovePosition 在物理步移动，碰撞和插值更正确。

**Q17. Trigger 和 Collider 的区别？**

A：Collider 产生物理分离；Trigger 只检测重叠，不阻挡。进球用 Trigger，边界用 Collider。

**Q18. Animator 的 Root Motion 是什么？**

A：动画自带位移驱动角色。本项目关闭 Root Motion，位移由 PlayerMotor 控制，避免动画和输入抢位移。

**Q19. Humanoid 和 Generic 的区别？**

A：Humanoid 有统一人形骨骼映射，可复用 Mixamo 动作；Generic 绑定具体骨骼，灵活但不能直接复用人形动画。

**Q20. 怎么在动画上覆盖骨骼？**

A：在 LateUpdate 里改 Bone 的 localRotation，或在 Animator 之后采样；动作结束恢复缓存的基础旋转。更正式的做法是 Layer + Avatar Mask + IK。

**Q21. OnGUI 为什么不适合正式 UI？**

A：IMGUI 每帧重建、布局开销大、适配和交互弱；正式项目用 UGUI/UI Toolkit。

**Q22. Canvas 的 Screen Space - Overlay 和 Camera 区别？**

A：Overlay 直接覆盖屏幕，不受相机影响；Camera 模式受相机/透视影响，适合世界空间 UI。移动端 HUD 通常 Overlay + CanvasScaler。

**Q23. 如何做移动端安全区？**

A：用 `Screen.safeArea` 把 Canvas 的锚点/边距限制在安全区；刘海、圆角、手势条都要考虑。

**Q24. 如何优化移动端性能？**

A：先 Profiler 定位：CPU 主线程、GC、Draw Call、Tris、overdraw。常见手段：对象池、合批、减少透明层、降低分辨率、减少每帧分配、LOD/剔除。

**Q25. Built-in 和 URP 的区别？**

A：Built-in 是老管线，材质/Shader 简单；URP 有可编程渲染、后处理、性能配置，但迁移成本和 Shader 兼容要评估。本项目先用 Built-in 验证手感。

**Q26. 如何做程序化球场？**

A：用 Mesh/材质/纹理程序生成，或 Editor 脚本批量创建；优点是快速迭代，缺点是生成物和场景文件的版本管理要规范。

**Q27. Android IL2CPP 和 Mono 的区别？**

A：IL2CPP 把 C# 转 C++ 再编译，性能和兼容性更好，支持 ARM64；Mono 是 JIT，迭代快但发布受限。正式包用 IL2CPP + ARM64。

**Q28. 构建失败怎么排查？**

A：先看 Console 第一条错误，再看 Editor.log、Gradle 日志；检查 SDK/NDK/JDK 版本、包名、签名、API Level、依赖冲突。

### 5.3 C# 类

**Q29. class 和 struct 的区别？**

A：class 引用类型、堆分配；struct 值类型、复制语义，适合小数据（Vector3）。不要把大对象做成 struct。

**Q30. 委托和事件的区别？**

A：委托是函数引用；事件是委托的封装，只允许外部订阅/取消，不能从外部触发。事件适合解耦 UI/系统。

**Q31. 协程和 Update 的区别？**

A：协程按时间分步、可读性好，但受 timeScale 影响、调试略难；Update 每帧执行，适合持续输入/状态。需要真实时间用 `WaitForSecondsRealtime`。

**Q32. 如何避免 GC？**

A：复用 List/数组、避免每帧字符串拼接、避免装箱、缓存组件、对象池；用 Profiler 的 GC Alloc 验证。

**Q33. 接口的作用？**

A：定义能力契约，降低耦合；例如 `IDamageable`、`IInteractable`。本项目规模小，主要用组件直接引用，正式版可抽接口。

**Q34. ScriptableObject 适合什么？**

A：配置数据、数值表、技能定义、关卡数据；可在编辑器调参，不依赖场景实例。

**Q35. 如何做状态机？**

A：枚举 + switch 适合小状态；复杂状态用类/接口或行为树。关键是明确进入/退出/转换条件，避免状态互相调用。

**Q36. 如何调试偶发 bug？**

A：固定复现步骤、记录输入/时间/状态、最小化场景；加日志和可视化轨迹；用 Git 检查点二分定位。

### 5.4 数学类

**Q37. 点乘和叉乘分别有什么用？**

A：点乘判断夹角/投影/前后；叉乘求法线、判断左右。项目中用点乘判断手势方向与相机前向，叉乘可做左右侧。

**Q38. 如何判断点在直线哪一侧？**

A：用直线法线与点到直线向量点乘，符号决定侧；绝对值是距离。

**Q39. 二次贝塞尔怎么求位置？**

A：`B(t) = (1-t)^2 P0 + 2(1-t)t P1 + t^2 P2`；P1 是控制点，决定弧线。项目中用于射门轨迹。

**Q40. 如何把屏幕方向映射到世界水平方向？**

A：取相机 forward/right 投影到水平面，归一化；`world = forward * screen.y + right * screen.x`，再 `y=0`。

**Q41. 四元数为什么比欧拉角好？**

A：四元数避免万向锁，适合插值（Slerp）和连续旋转；欧拉角适合编辑器和简单展示。

**Q42. 如何判断两条折线是否近似直线？**

A：计算每个点到起终点弦的垂直距离，取最大值除以路径长度；再结合路径/弦比。项目中阈值是 5% / 1.10。

### 5.5 游戏设计/产品类

**Q43. 这个游戏的核心循环是什么？**

A：开球 → 争球/带球 → 选择射门或花式 → 进球/被抢断 → 重新开球；比分或时间结束 → 结算 → 再来一局。

**Q44. 目标用户是谁？**

A：喜欢足球、动漫、短局竞技手游的玩家；一局 90–150 秒，适合通勤/课间。

**Q45. 怎么设计新手教学？**

A：只教一个动作：摇杆移动 → 球上拖动射门 → 球外直线爆发 → 球外弯折花式 → 进入比赛。每步一个通过条件，可跳过。

**Q46. 怎么评估花式系统？**

A：看识别成功率、使用率、成功过人率、失误率、玩家是否能用语言描述“直线/弯折”的规则；不能只看动画帅不帅。

**Q47. 数值怎么定？**

A：先定体验目标（射门 0.3–0.5s 前摇、爆发 0.1s、单局 2 分钟），再用可调参数逼近；不要先堆表格。当前参数是手感值，不是平衡值。

**Q48. 如果做商业化，怎么不破坏手感？**

A：先保证基础比赛完整，再做外观/球场/动作皮肤；避免付费影响射门/花式判定。当前 Demo 不做商业化。

### 5.6 行为类

**Q49. 你最有成就感的部分？**

A：把“球上射门/球外花式”的输入争抢收敛成两层规则，并让花式方向跟末段切线一致；这是从“功能堆叠”到“可解释手感”的转变。

**Q50. 你最大的不足？**

A：表现层完成度低：正式动作、音效、VFX、UI 和 Android 真机都没做完；我倾向于先做闭环，这会牺牲展示完成度，下一阶段要补。

**Q51. 和策划/美术协作时怎么沟通？**

A：用可运行的灰盒和参数表沟通，不用口头描述；把“想要的手感”拆成时间、距离、镜头、反馈四类，逐项验收。

**Q52. 为什么选择独立完成？**

A：原型阶段需要快速试错，独立完成能保证输入、镜头、球权的一致性；但正式版需要分工和管线。

## 9. 快速复习卡

### 9.1 五个必须能画出来的图

1. 输入状态机：PointerDown → Shot/Dribble → Release → Burst/Elastico。
2. 球的物理/球权关系：BallSimulator + PossessionManager + TackleSystem。
3. 动作时序：识别 → commit → 0.12s 爆发 → 0.34s 伸腿 → 0.60s 慢动作。
4. 相机层级：玩家 root → 相机 pivot → 越肩偏移 → 球心 look。
5. 项目架构：Input / Player / Ball / Camera / Match / UI。

### 9.2 五个必须能解释的数字

- 42×26m 球场，3 球 / 120 秒。
- 0.12s 爆发，0.34s 伸腿，0.60s 花式慢动作。
- 5% 偏离 / 1.10 路径比。
- 7.5 m/s 移动，6 m/s 带球，16 m/s 爆发峰值。
- 58° → 42° FOV。

### 9.3 五个“如果面试官追问”

- 为什么不用 UGUI？→ 原型阶段 OnGUI 快；正式版会迁 UGUI。
- 为什么没有真机包？→ SDK/NDK 未装；代码和构建配置已准备，但没有把未验证的东西说成完成。
- 为什么只有一种花式？→ 先验证输入规则；多花式会放大误判和动作资产成本。
- 为什么不用行为树？→ 单层 AI 足够验证攻防；P2 再换。
- 为什么不做联网？→ 核心手感未锁定，联网会掩盖输入/镜头问题。
